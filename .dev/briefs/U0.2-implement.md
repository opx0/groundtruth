# U0.2 implementation brief — the evidence kernel

## GOAL

Build the evidence kernel so that a SEMS site record, read from the committed
fixture bytes, renders as one factual sentence and every displayed value in it
traces back to the raw source field it came from. The four product guarantees
must be enforced by the compiler or by a test, not by a reviewer noticing.

## CONTEXT, read in this order

1. `.dev/designs/SYNTHESIS.md` — the decision and the five grafts. Authoritative.
2. `.dev/designs/arm-a.md` section 2 — the type sketch you are building.
   SYNTHESIS.md overrides it wherever they disagree.
3. `docs/BRIEF.md` sections B4, B5, B8, and A3. A3 is the trace panel you must
   be able to produce.
4. `tests/fixtures/sems/*.json` — real unedited bytes. Design to these.

Arms B and C are in `.dev/designs/` for reference. You do not have to read them.
Their contributions are already folded into SYNTHESIS.md.

## SCOPE

You may create and edit:

- `lib/evidence/**` — the kernel.
- `lib/templates/**` — the SEMS templates only.
- `tests/unit/evidence/**` — your tests.
- `eslint.config.mjs` — to add the graft 5 rule, and nothing else.

You may not touch `app/`, `lib/adapters/`, `docs/`, `.dev/PLAN.md`, or any
other file. Do not build the live SEMS adapter. Reading the fixtures from disk
in a test helper is the right level for this unit.

## ACCEPTANCE

Each of these is checkable. All must hold.

1. `pnpm verify` passes, meaning typecheck, unit tests, and lint are all clean.
2. A test renders the nearest SEMS record from
   `tests/fixtures/sems/arcgis-5mi-houston.json` joined to
   `tests/fixtures/sems/envirofacts-TXN000622182.json` and asserts the exact
   sentence text against a literal string.
3. A test traces the distance span of that sentence and asserts it carries the
   formula name and all four input coordinates, each with its own provenance.
4. A test asserts both `HOUSTON REFINERY` and `VALERO PLUME` are reachable from
   the trace of that one record, since the two sources name the same site
   differently.
5. A test deletes the record from the store and asserts that rendering and
   tracing both return nothing for it.
6. A test asserts a status string the code has never seen survives verbatim.
   Use a fixture value, not an invented one.
7. Four type-level tests, each a snippet that must fail to compile, verified
   with `// @ts-expect-error`: a template naming a field of the wrong record
   kind, a clause with no field reference, a clause interpolating a plain
   string, and an adapter-shaped object trying to supply its own
   `distanceMeters`.
8. A test asserts the ESLint rule banning type assertions under `lib/evidence/`
   is configured and reports a violation on a fixture snippet.
9. Dates: `1710413511000` renders as a UTC ISO instant, and
   `"2022-02-08 00:00:00"` renders as `2022-02-08`. Assert both literally.
10. A record whose coordinate is null produces a null location and a null
    distance without throwing. There are such rows in the fixture.

## VERIFY

```
pnpm verify
```

Paste the real output in your report. A failing or skipped check is not a pass.
`pnpm test` alone is not sufficient, the typecheck is where most of these
guarantees actually live.

## FORBIDDEN

- No `any`, no `as` assertions, no non-null `!` inside `lib/evidence/`. The
  guarantee is the point of the unit.
- No network calls. No new dependencies. Zod 4 and vitest are already here.
- No git commands. Do not commit. Leave the working tree dirty for review.
- No edits outside the SCOPE list.
- Do not weaken an acceptance item to make it pass. If one is genuinely wrong,
  stop and say which and why in your report.

## TIMEBOX

Roughly 60 minutes. If you run out, return what compiles and passes, and name
precisely what is unfinished. Partial and honest beats complete and claimed.

## REPORT, 25 lines maximum

Files created. The exact `pnpm verify` output. Each of the ten acceptance items
marked pass or fail with the test name that proves it. Anything you had to
deviate from in SYNTHESIS.md and why. Anything you believe is wrong with the
design that you implemented anyway.
