# U0.2 — Evidence kernel design brief

You are designing the load-bearing core of Ground Truth. Read `FINAL-IDEA.md`
sections B4, B5, B7, B8 and section A3 before anything else. Read the real
payloads under `tests/fixtures/`. They are unedited government API responses.

## The product rule the code must enforce

Ground Truth renders factual sentences about an address from government
records. No language model writes a factual sentence. Every displayed value
must be traceable, at runtime, to the raw source field it came from. Clicking
any sentence opens a panel showing, per displayed value: the raw field name,
the raw value, the normalized value, the transform name, the adapter version,
the record and retrieval dates, and for a distance, both input coordinates and
the formula.

## What you are designing

The kernel every adapter, the selection policy, the renderer, and the trace
panel depend on. Concretely:

1. How a provenance-carrying value is represented and constructed.
2. How an adapter turns raw bytes into typed records without hand-writing
   provenance for every field at every call site.
3. How a record kind is bound to the templates allowed to render it, so a
   template cannot render the wrong kind. This must fail at compile time if
   possible, at test time otherwise.
4. What a rendered sentence *is*, such that the trace panel can map a clicked
   piece of that sentence back to the exact provenance behind it, and such that
   deleting a record provably removes its text.
5. How a source failure, a no-data result, and a success are represented so one
   failing source cannot block the report.

## Hard constraints

- TypeScript, strict, with `noUncheckedIndexedAccess` and
  `exactOptionalPropertyTypes` already on. Zod 4 is available.
- Adapters run server-only and receive coordinates, never the raw address.
- Unknown source status codes are preserved verbatim, never mapped or guessed.
- Distances are computed, never read from a source, and carry both coordinates.
- ArcGIS dates arrive as epoch milliseconds. Envirofacts dates arrive as
  `"2022-02-08 00:00:00"`. Census returns no match-type field at all.
- The same site has different names in two sources. In the fixtures,
  registry 110000460885 is `HOUSTON REFINERY` in the ArcGIS layer and
  `VALERO PLUME` in Envirofacts. Both must survive to the trace panel.
- Some fixture coordinates are null. Some accuracy values are null.

## Deliverable

Write your design to `.dev/designs/<your-arm>.md`. It must contain:

- **Usage first.** The caller's code, written out, before any type definition:
  a SEMS adapter producing one record from the fixtures, the selection step,
  the renderer producing one sentence, and the trace panel reading it back.
- **The types.** Full TypeScript, signatures and type definitions only, with
  `not implemented` bodies. It must compile in principle under the tsconfig.
- **The mechanism for each of the five numbered items above**, in one short
  paragraph each, naming what makes the guarantee hold.
- **Two things your shape makes hard**, honestly. Not hedges, real costs.
- **The test that would catch a violation.** For each of: wrong-kind template,
  a value mutated after validation, a record deleted but its text remaining,
  a sentence rendered with no provenance.

## Rules

- Design the whole shape. Do not describe a variation on an obvious approach.
- Prefer a small public surface that hides a lot. Reject pass-through layers,
  shallow wrappers, and modules named after pipeline phases (parse, validate,
  transform). Execution order is not ownership.
- Do not write implementation code. Do not create files outside
  `.dev/designs/`. Do not install packages. Do not run git.
- Budget: roughly 20 minutes of work. Return partial rather than overrun.

## Report back, 20 lines maximum

The file path you wrote. Your central structural idea in two sentences. The
five mechanisms as one line each. The two costs. Nothing else.
