# U0.3 — close four kernel gaps before the adapters fan out

The kernel in `lib/evidence/` is committed and green. Its implementer flagged
four gaps against its own work. All four are real. They are being fixed now
rather than later because six adapters are about to be written against this
shape, and changing a record field afterwards costs six times as much.

Read `.dev/designs/SYNTHESIS.md` and `lib/evidence/records.ts` first.

## Gap 1: the government record link has no provenance

`Provided<K>.sourceUrl` is a plain `string`. It is the one displayed value in
the product with no trace behind it, and it is the value the entire pitch asks
the reader to click. An adapter builds it by interpolating an ID into a URL
template, so an interpolation bug produces a confident link to the wrong
record and nothing catches it.

Make it `Sourced<string>`, derived from the identifier field it interpolates,
so the trace panel shows which raw field produced the link and the URL template
that shaped it. The existing computation provenance already carries inputs;
this is another computation, not a new mechanism.

## Gap 2: two different agencies' status fields share one record field

`nplStatus` currently reads Envirofacts `npl_status_name` and silently falls
back to the ArcGIS layer's `ACTIVE_STATUS` when no Envirofacts row joined.
Those are different fields from different systems with different vocabularies.
Envirofacts says `Not on the NPL`. The FRS layer says `NOT ON THE NPL`. They
agree here and will not always agree, and the brief forbids guessing what a
source status means.

Split them. `semsNplStatus` reads Envirofacts only and is null when no row
joined. `frsActiveStatus` reads the ArcGIS layer only. Neither substitutes for
the other. The template decides what to render when one is absent, and that
decision becomes visible and testable rather than buried in the adapter.

## Gap 3: the trace walks only one level

`Trace.values` enumerates `Sourced` fields at the top level and inside
`GeoPoint`. A `Sourced` nested deeper in a future container is silently absent
from the panel, which means a displayed value with no row in its own trace.

Walk the record generically to any depth. Add a test with a record carrying a
`Sourced` two containers deep and assert it appears.

## Gap 4: the fan-out path is untested

`runSources` and `storeOfSources` are implemented but only `runSource` has
tests. These are the functions that make one failing source not block the
report, which is a headline promise of the product.

Test, using fake adapters, that: every source ID appears in the result whatever
happened; one adapter throwing leaves the others `ok`; one adapter timing out
leaves the others `ok`; an adapter returning zero records produces `no-data`
and not `ok`; and an adapter whose source answered with an error body produces
`unavailable` carrying the raw code unmapped.

The last one matters. `tests/fixtures/fema/esri-error-bad-geometry.json` is an
ArcGIS error delivered with an HTTP 200 status. Anything that trusts the status
code reads it as success. Prove the kernel does not.
