# Adapter units, shared brief

Five adapters are being written in parallel, one per agent. Read this, then
your own section in the message that spawned you.

## What an adapter is

A server-only module that fetches from one government endpoint, validates the
response, and returns typed records the kernel seals. It never writes text and
never decides what the report shows.

## Read first

- `lib/evidence/index.ts` for the exported surface.
- `lib/evidence/records.ts` for `Provided`, `Built`, and your record kind. Your
  kind is already declared. Do not edit this file.
- `lib/evidence/sourced.ts` for the readers: `fieldsOf`, `haversine`,
  `coalesce`, `urlFrom`, `absent`.
- `lib/evidence/source.ts` for `Adapter`, `SourceIo`, and the three outcomes.
- `tests/unit/evidence/helpers/sems-fixtures.ts` for a worked example of
  reading a fixture and building a record. Copy its approach.
- `tests/fixtures/README.md`. **Read this properly.** It lists the traps each
  payload exists to pin, and most of them will bite you.

## Rules that are not negotiable

1. **Never hand-write provenance.** Read every value through a `fieldsOf`
   reader. If you find yourself constructing a `Provenance`, stop, you are
   using the kernel wrong.
2. **No type assertions, no non-null assertions, no `any`** anywhere under
   `lib/adapters/`. Lint enforces this and the rule is not to be touched.
3. **Status and category text is passed through verbatim.** Never map an
   agency's vocabulary onto ours, never `z.enum()` a status field, never
   collapse an unknown code to "unknown". A status the code has never seen must
   reach the screen unchanged.
4. **Check for an error body, not just the HTTP status.** Both ArcGIS and ECHO
   return failures with HTTP 200. The two use different error shapes.
5. **Zero results is `no-data`, not `ok` and not a failure.**
6. **The adapter receives a `Locus`, which carries coordinates and no address.**
   There is no address field to read and you must not add one.
7. **Do not create shared helper modules.** Keep everything your adapter needs
   in your own file even if it duplicates another adapter. A later unit
   deduplicates once all five exist. Touching a shared file would serialize
   five agents that are deliberately running at once.

## Scope

You may create exactly two files: `lib/adapters/<yours>.ts` and
`tests/unit/adapters/<yours>.test.ts`. Nothing else. Not `lib/evidence/**`,
not `app/**`, not `docs/**`, not `.dev/**`, not `eslint.config.mjs`, not any
other adapter.

If you believe a kernel change is required, do not make it. Say so in your
report and work around it.

## Acceptance

- `pnpm verify` green. Paste the real output.
- Tests read the committed fixtures from `tests/fixtures/`. Never invent a
  payload when a real one exists.
- Assert literal expected values: exact strings, exact numbers, exact dates.
  A test that would pass if every field were undefined is not a test.
- Cover: a successful parse, zero results, a field that is null on a real row,
  a status string the code does not know, and the source's error body.
- A live network call is allowed in a test only if it is skipped by default.
  The suite must pass with no network.

## Forbidden

No new dependencies. No git commands, leave the tree dirty. Do not weaken an
existing test. Do not edit another agent's files even if they look wrong.

## Timebox

45 minutes. Return what is green and name precisely what is unfinished.

## Report, 20 lines maximum

Files created. Real `pnpm verify` output. What each test proves, one line each.
Every fixture trap that actually bit you. Anything you think is wrong.
