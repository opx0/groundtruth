# U1.8 — pay down the kernel debt the five adapters found

Five adapters were written in parallel against the kernel. They were forbidden
from editing it and told to report what they had to work around. This unit
fixes what they found. `.dev/PLAN.md` holds the full queue; the items below are
in priority order and the first two are the ones that matter.

Read `lib/evidence/sourced.ts` closely before changing anything. Every existing
guarantee stays intact. `bash .dev/census/mutation-check.sh` must still report
six of six after your changes.

## 1. The trace reports a value the source did not send

ECHO sends a penalty as the string `"$0"`. The kernel's number reader throws on
a currency symbol, so `lib/adapters/echo.ts` strips it before reading. The trace
panel then names the field and the transform correctly but reports the raw value
as `"0"`, when EPA sent `"$0"`.

That is a false statement about a government source, displayed inside the one
panel whose entire purpose is reporting exactly what the source sent. It is
small and it is the single worst defect in the codebase, because it is the
product's own promise broken in miniature.

Add a `parse-currency` transform and a reader for it. The original string stays
in provenance. Update the ECHO adapter to use it and drop the caveat that
apologises for the old behaviour.

## 2. No reader builds a structured value, and three adapters hit it

`Sourced<T>` can only be built for scalars. Three adapters needed otherwise:

- `lib/adapters/echo.ts` needs a list of programme statuses.
- `lib/adapters/frs.ts` needs a list of programme interests.
- `lib/adapters/census.ts` needs an address range of two strings.

The first two fell back to a query-level provenance naming a request parameter,
so each programme's compliance status currently displays with no trace to the
field it came from. The third could not use the kernel's declared `GeocodeMatch`
at all, because that type is unconstructable without hand-writing provenance,
and exported its own near-identical type instead.

Add a reader that builds a structured value while keeping per-element field
provenance. Then migrate all three adapters onto it, and reconcile the
geocoder's local type back into `lib/evidence/records.ts` so there is one
`GeocodeMatch` again. Arm B predicted this gap in the design race; see
`.dev/designs/arm-b.md`.

## 3. A status that could not be fetched is not a status that is absent

`lib/adapters/sems.ts` fails the whole Superfund source when one Envirofacts
request errors. Its reasoning is right: the registry-only sentence claims the
inventory returned no status row, and after a failed request that is a lie.

The blast radius is wrong. All fifteen sites in the Houston fixture do have a
status row, checked live, so this fires on a network blip and throws away
fourteen good sites to avoid one false sentence.

Add a third state so a record can say its status could not be retrieved. This is
the no-data versus unavailable distinction the report already makes for whole
sources, applied one level down. Add the template for it.

## 4. Smaller items, in order

- `SourceIo.get` constrains `Raw` to `JsonObject`, so a top-level JSON array
  cannot be expressed. Envirofacts returns one. Widen to `JsonValue` and drop
  the workaround in `lib/adapters/sems.ts`.
- ECHO dates are `08/12/2024` while SEMS dates are `2022-02-08`. Add a
  `parse-us-date` transform so record kinds are consistent. The raw string stays
  in provenance, which is why the ECHO adapter refused to rewrite it by hand.
- An adapter cannot supply its own no-data note, so the flood card cannot say
  which of its two datasets returned nothing, which is the one distinction that
  card exists to make. Let an adapter supply the note.
- One Superfund report makes fifteen parallel Envirofacts requests, unthrottled.
  Cap the concurrency.
