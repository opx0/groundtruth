# U2.0 — the record templates that do not exist yet

`lib/templates/` holds templates for three of the five subject scopes and for
exactly one of the six record kinds. `sems-site` has five templates. The other
five kinds have none, so `TemplateRegistry` — the type in
`lib/evidence/templates.ts` that says every kind has an allowlist of at least
one template — has never been instantiated. Nothing can render an ECHO
facility, a FEMA flood zone, an FRS facility, an AQS monitor summary or an
AirNow observation.

This unit writes those templates. The selection policy (U2.1) chooses between
them; the report route (U3.1) renders them.

## Reading order

1. `lib/templates/sems.ts` — the shape to copy, including the module comment
   that explains which template prints when and why. Read it first.
2. `lib/evidence/templates.ts` — `defineTemplate`, `sentence`, `fallback`,
   `km`, `SlotKeys`. What a clause may reference and what it may not.
3. `lib/evidence/records.ts` — the fields of your kind. Only fields typed
   `Sourced<...>` are referenceable; an array of objects
   (`programInterests`, `programStatuses`) is not a slot and a template cannot
   name it.
4. `docs/BRIEF.md` A2 (the sentences the product promises), B8 (rendering
   rules), B10 (failure wording), C2 (words that never appear).
5. `tests/fixtures/README.md` and the fixtures for your source, so every
   sentence you write is a sentence the real fields can actually fill.

## The rules that make this unit different from writing copy

**A template holds no values and cannot branch.** There is no conditional, no
ternary, no default. If the sentence differs depending on a value, that is two
templates and the selection policy picks one. `lib/templates/sems.ts` has four
templates for one kind for exactly this reason; its module comment says so.

**A clause needs at least one reference.** `sentence\`No data.\`` does not
compile. Connective text lives inside a clause that carries references, so a
caveat cannot outlive the value it is about.

**A missing slot removes its clause, and a missing slot in a clause removes
the whole clause.** Put each independent fact in its own clause. Do not write
one long clause that disappears entirely because one optional field is null.

**`fallback(field(x), "...")` keeps a clause alive when the value is null**,
and the span still points at the slot so the trace shows the null's
provenance. Use it only where a stated absence is better than a dropped
clause — `sems.ts` uses it for "Date unavailable", which is B10's wording.

**`km(field(x))` renders a metre count as "0.71 km".** Only for numeric slots.

**A boolean slot renders as the string `true` or `false`.** That is never
acceptable on screen. A boolean decides *which template*, it is never printed.

**Never write a claim `docs/BRIEF.md` C2 forbids.** "Safe", "unsafe", "risk",
"polluter", any verdict, any severity, any cumulative judgement. State the
field and stop. If a sentence you want to write is not supported by a field on
the record, delete the sentence — do not soften it.

**Use the agency's own vocabulary verbatim.** A status string is printed as
sent. Do not map, title-case, expand or explain a code. If the sentence needs
a word the source did not send, the sentence is wrong.

## File scope

You own exactly two new files, named in your task. Nobody else writes them.

Read anything. Write nothing else. In particular do not edit
`lib/evidence/**`, `lib/templates/sems.ts`, `lib/templates/sections.ts`,
`lib/templates/sources.ts`, `lib/templates/origin.ts`,
`lib/templates/groups.ts`, `lib/templates/registry.ts`, `lib/adapters/**`,
`app/**`, `docs/**` or any existing test file. Four other agents are writing
sibling files in the same directory right now.

If you need a kernel change to say something honestly, do not make it. Write
the honest smaller sentence, and say in your report what you could not say and
what it would take.

## Acceptance

- `pnpm exec tsc --noEmit` clean and `pnpm exec eslint <your two files>` clean.
  A targeted `pnpm exec vitest run <your test file>` green. Paste real output.
- Every template is exported, and a `<kind>Templates` array exports all of
  them, exactly as `semsTemplates` does.
- A test renders each template against a record built from a committed
  fixture, and asserts the **exact** rendered string. Not a substring, not a
  regex — the whole sentence.
- A test proves a template whose record is removed from the store renders
  null.
- A test proves at least one optional-field-null case drops its clause and
  leaves the rest of the sentence standing.
- A test asserts a trace for one span: the field name and the raw value behind
  it.
- Zero type assertions (`as`), non-null assertions (`!`) or `any`.
- A module comment in the same register as `lib/templates/sems.ts`: which
  template prints when, and which judgement calls you made about wording and
  why.

## Forbidden

No new dependencies. No network. No git commands — leave the tree dirty.

## Report, 20 lines maximum

The two files. Real command output. Each template's id and its exact rendered
sentence against a real fixture, one line each. Every wording judgement you
made. Anything you had to leave unsaid because no field supports it.
