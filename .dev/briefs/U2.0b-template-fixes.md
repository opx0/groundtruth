# U2.0b — fixing what three reviews found in the record templates

Three adversarial reviews ran over `lib/templates/{echo,fema,frs}.ts`. One
audited claims against the fields, one audited kernel rules, one rendered every
template against every committed fixture and printed the matrix. Between them
they found one structural hole and about a dozen sentences that say more than
the record supports.

The kernel has already been changed to close the structural hole, and two of
the wording fixes need record fields that now exist. Read this whole file
before touching anything: several fixes are only correct together.

## What changed in the kernel, and what you do with it

### 1. A template can now declare the state it speaks about

`defineTemplate` takes an optional fourth argument: a list of `Requirement`s.
`assemble` refuses to render the template when the subject does not satisfy
them. Read `Requirement` in `lib/evidence/templates.ts` and `satisfies` in
`lib/evidence/sentence.ts`.

```ts
export const example = defineTemplate("echo-facility", "echo-facility/x@1", (field) => [
  sentence`…`,
], [{ slot: "complianceStatus", present: false }]);
```

Three forms: `{ slot, equals }`, `{ slot, present: boolean }`,
`{ state, is }` (for a tagged outcome like `sems-site`'s `statusRow`).

This exists because the kind gate stops a Superfund template rendering an ECHO
record but does nothing to stop the *wrong* template rendering the *right*
record. The fixtures review proved it: `echo-facility/no-status@1` rendered
"EPA ECHO reported no compliance status for registry ID 110009747514" over a
record whose status is `Violation Identified`, and both FEMA SFHA templates
rendered over the same row, asserting opposite things about the same point.

**Every template that asserts a state must now declare it.** A template that
only prints values it references needs no requirement.

### 2. `day()` beside `km()`

`day(field("sourceUpdatedAt"))` prints the date part of an instant:
`2024-03-14T10:51:51Z` renders as `2024-03-14`. The trace keeps the instant as
the normalized value. `docs/BRIEF.md` A3's own trace row shows this field that
way.

### 3. Two new fields on `fema-flood-zone`

- `sfhaLabel: Sourced<string | null>` — `SFHA_TF` read through the new
  `map-code` transform as `"inside the Special Flood Hazard Area"` /
  `"outside the Special Flood Hazard Area"`, null for any other letter. The
  phrase is now a value with a trace instead of connective text.
- `datasetLabel: Sourced<string>` — `"FEMA's National Flood Hazard Layer"` or
  `"Esri's reduced-set copy of FEMA's National Flood Hazard Layer, dated
  2026-03-11"`, provenance the request we made, like `dataset`'s.

## The findings, per file

### `lib/templates/fema.ts`

1. **The load-bearing phrase had no field behind it.** `inside the Special
   Flood Hazard Area` was connective text in a clause whose only slot was
   `zoneCode`. Collapse the three templates into **one**, using `sfhaLabel`:
   `The mapped point is in zone ${field("zoneCode")}, ${fallback(field("sfhaLabel"), "…")}.`
   Choose the fallback wording carefully: `flag`/`map` return null for an
   unmapped letter, for a JSON null, **and** for `""`, and sibling string
   columns in the same recorded rows do carry `""`. So the fallback must be
   true for all three. "a letter this report does not map" is not.
2. **DFIRM_ID is not a panel and does not "cover" anything.** The committed
   fixture carries FEMA's own column description: *"Study Identifier… the
   two-digit State FIPS code, the three-digit county FIPS code and the letter
   'C' (e.g., 48107C). Within each FIRM Database, the DFIRM_ID value will be
   identical."* `48201C` is Harris County's FIRM database. Panels live in
   `S_FIRM_Pan.FIRM_PAN` and look like `48201C0810L`. Two unsupported words in
   one clause: "panel" renames the field, "covers the mapped point" asserts a
   spatial relation the field does not state. Say what it is:
   `FEMA's FIRM study identifier for this area is …`. `docs/BRIEF.md` A2 has
   the same error and is being corrected separately — do not edit it.
3. **Values from Esri's copy were attributed to FEMA four times per card.**
   When `dataset` is `ESRI_REDUCED_SET` the adapter's own caveat says the
   values came from Esri's copy, *not* FEMA's service, and that caveat reaches
   only the trace. De-attribute the clauses that are just column readouts
   (`The zone subtype recorded for this area is …`), and print
   `datasetLabel`, never the enum.
4. **`sourceCitation` is not a citation.** FEMA's own description: *"Abbreviation
   used in the metadata file… must match a value in L_Source_Cit."*
   `48201C_FIRM1` is a lookup key. Name it as one.
5. **Drop the parcel caveat from the zone clause.** "The point is a
   street-segment interpolation, not the parcel boundary" is a fact about the
   `origin` subject, asserted inside a `fema-flood-zone` template, in a clause
   whose only slot is `zoneCode` — clicking it opens FLD_ZONE and explains
   nothing. It stays a record caveat (the adapter already carries it) and the
   report will place the origin sentence on the card, which carries the range,
   side and TIGER line that actually establish interpolation.

### `lib/templates/echo.ts`

6. **`no-status@1` stated a falsehood on 6 of 7 real rows.** Requirement:
   `complianceStatus` not present. `summary@1` and `noncompliance@1` need the
   matching requirements so the three cannot overlap.
7. **`formal-action@1` collapsed to a bare lead clause on 6 of 7 rows**,
   producing a sentence byte-identical to another template's. Require
   `lastFormalActionDate` present.
8. **A null `lastFormalActionDate` reads as "no enforcement history".** It
   only supports "this summary column is empty". Add a stated-absence template
   the way `no-status@1` does it, and reword: the column is ECHO's facility
   summary, not a complete history. `Last` implies completeness.
9. **"Most recent penalty: $0" states that a penalty of zero dollars was
   assessed.** `FacLastPenaltyAmt` is the literal string `"$0"` on all seven
   rows, including six with `FacPenaltyCount: null` and
   `FacDateLastPenalty: null` — facilities with no penalty at all — while B14
   records $20,254,146 of real penalties within the same 5 miles. Name the
   column rather than asserting the amount, and split the date out.
   (`formatValue` also prints a parsed number, so a real amount would render
   `$20254146`, losing ECHO's grouping. Note it; do not add a currency
   display format in this unit.)
10. **"Penalty actions on record" claims an unbounded history.** ECHO's own
    metadata returns `Description: null` for `FAC_PENALTY_COUNT` (see
    `tests/fixtures/echo/metadata.json`), so nothing retrieved supports "on
    record", which a reader takes as all-time. Name the column.
11. **An unqualified compliance status reads as today's status.** The record's
    own caveat says the column covers the last twelve quarters and is not a
    statement about conditions today; that caveat reaches only the trace, and
    C2 forbids "Real-time environmental history". `lib/templates/sections.ts`
    rewrote A2's "current noncompliance" for exactly this reason — match it.
12. **A code list rendered as one code.** `FacSICCodes` is `"2048 5171"` in the
    real bytes. "under SIC 2048 5171" reads as a single code. Phrase it as the
    list it is.
13. **The distance never says what it is from.** `semsSiteNpl` says "from the
    mapped point"; these do not, and `industry-codes@1` is designed to stand
    alone.
14. **`industry-codes@1` repeats the lead clause**, so a card rendering it
    beside the summary prints the facility's name and distance twice. Drop the
    lead clause; name the subject inside each clause instead, so the template
    renders null when both columns are null rather than echoing a lead clause.
15. **Leave `INC., 0.30 km.` alone.** The fixtures review flagged
    `SOUTH-PORT SYSTEMS, INC., 0.30 km.` as a period-comma collision. It is
    not: retaining an abbreviation's period before a comma is standard English.
    Put a line in the module comment saying so, so it is not re-litigated. The
    real hazard, a name in clause-final position rendering `INC..`, is what
    `lib/templates/frs.ts` avoids, and no ECHO template has one.

### `lib/templates/frs.ts`

16. **A superlative over a set where two thirds of the members have no value.**
    25 of registry 110000460885's 38 rows carry `UPDATE_DATE: null`. "The most
    recently updated of its programme-interest rows" is not supported; "the
    latest update date FRS carries on any of its rows" is.
17. **A clock time and a UTC offset FRS never stated.** Use `day()`.
18. **"this facility" in `cross-reference@1` is a deixis onto whatever the
    selection policy placed above it.** Under a B6 rule-3 "Possible match" it
    silently upgrades a suggested group to an identity claim. State the
    registry's own fact instead, and keep the name out of clause-final
    position.

### `lib/templates/sems.ts`

19. **All five templates need requirements.** Four of them assert something
    about what the Superfund inventory answered, and any of them would render
    over a record in any of the three `statusRow` states. Use
    `{ state: "statusRow", is: … }`. `sems-site/npl@1` asserts the site is on
    an NPL list and should require `semsNplStatus` present.
20. **`semsSiteRegistryOnly` and `semsSiteStatusUnavailable` both lead with
    "it"** after a clause that ends on `distanceMeters`. That is fine. What is
    not fine is that the registry-only wording claims the inventory answered
    with no row; with requirement 19 in place, it cannot render otherwise.
    Say so in the module comment where it currently says the selection policy
    is what keeps them apart.

## Test findings you must also fix

- **The FEMA no-boolean test is vacuous.** It asserts
  `not.toMatch(/\b(true|false)\b/)` over three hand-curated (record, template)
  pairs, never the cross product, so it passed while the defect was live.
  Every template-level property test must run over **every template × every
  record** built from the fixtures.
- **`tests/unit/templates/echo.test.ts` has two loops whose variable never
  enters the assertion** — they re-render the same record N times. Fix them to
  iterate records.
- **The derived FEMA row's honesty comment is wrong.** It claims to hash "its
  own bytes" but hashes a re-serialisation of the *zod-parsed* 7-key subset,
  not altered original bytes. It also alters two fields where one would do, so
  the zone `AR/AE` is a value no recorded payload carries. Fix the comment to
  say what it actually hashes, and alter only the field the test needs.
- Add a test per file that renders **every** exported template against
  **every** record built from that source's fixtures and asserts that a
  template whose requirements do not hold renders null. That is the test that
  would have caught findings 1, 6 and 7.

## Scope

Four agents, four disjoint sets. Yours is named in your task. You own one
template file and its test file, and nothing else.

Do not edit `lib/evidence/**`, `lib/adapters/**`, `docs/**`, `.dev/**`,
`tests/fixtures/**`, another agent's template file, or any test outside your
own. The kernel and the two new FEMA record fields are already in place; if you
need another kernel change, do not make it — say so in your report.

## Acceptance

1. `pnpm exec tsc --noEmit` clean, `pnpm exec eslint <your files>` clean,
   `pnpm exec vitest run <your test file>` green. Paste real output.
2. Every finding for your file is addressed or explicitly refused with a
   reason. Number your report against the numbers above.
3. Exact whole-string assertions, from records built through the real adapter
   code and the kernel's `complete`.
4. A cross-product test: every exported template × every record from your
   source's fixtures, asserting either the exact rendered string or null.
5. Zero type assertions, non-null assertions or `any`.
6. The module comment is updated to match what the file now does, including
   the requirements each template declares and why.
