# U2.2 — facility grouping

`docs/BRIEF.md` section B6 defines how records from different sources are tied
together. Implement it as a pure function over records, in a new file.

## The rules, in order of confidence

1. An exact FRS registry ID match creates a **confirmed** group.
2. An exact programme ID match creates a **confirmed** programme link.
3. Similar names plus nearby coordinates create a **suggested** group, which
   must carry a visible "possible match" label wherever it is shown.
4. When two sources give different coordinates for one grouped thing, the
   distance uses the FRS coordinate and the other stays visible.

Every grouped record keeps its own source ID, its own name, its own coordinate
and its own link. Grouping never merges records into one, and it never claims
that an inferred match is one legal or physical facility. It annotates.

## What the real data looks like

- `tests/fixtures/frs/arcgis-registry-110000462703-two-ids.json` holds two
  Superfund site IDs under one registry ID. That is rule 1.
- Registry `110000460885` is `HOUSTON REFINERY` in the ArcGIS layer and
  `VALERO PLUME` in Envirofacts. One thing, two names, both true.
- `tests/fixtures/frs/arcgis-registry-110000460885.json` has 38 programme
  interest rows across 15 programmes for one facility.
- ECHO facilities and SEMS sites both carry a registry ID, which is what makes
  rule 1 possible across sources.

## Design notes

Confidence is part of the data, not a comment. A caller must not be able to
treat a suggested group as a confirmed one by accident, so make the distinction
structural rather than a boolean field that is easy to ignore.

Be conservative with rule 3. A false "possible match" between two unrelated
facilities is worse than no group at all, because the reader is being told two
records might be the same place. Name your similarity threshold, justify it, and
write a test with a near-miss pair that must not group.
