# U2.3 — the four claim scopes the report still cannot render

`Placement` in `lib/evidence/sentence.ts` only has a `record` scope. The census
in `.dev/census/` counts every claim the brief requires the report to make and
finds that six of twenty-six are about a single record. The other twenty are
about something else, including the report's headline sentence.

Run `node .dev/census/census.mjs` to see the split. Read
`.dev/designs/SYNTHESIS.md` graft 1, which is the decision you are implementing.

## The four scopes to add

**`section`.** One source's records within its stated boundary. This is where
counts live, and **a count must be the length of the ordering, never a number
anyone wrote down**. That is the whole point: removing a record lowers the count
by itself, so the deletion guarantee holds for aggregates the same way it holds
for records. A section claim's provenance is the query behind it, meaning the
endpoint, the boundary, the retrieval time, and the record IDs counted. Never a
synthetic record; inventing a row no agency returned is the one thing this
product promises never to do.

Required sentences, from `docs/BRIEF.md` A2 and B7: how many sites a source
lists within the boundary, how many of those are on the final National
Priorities List, how many facilities have a formal enforcement action, how many
are in current noncompliance, and the "no matching records within the stated
boundary" wording.

**`source`.** One source's outcome. Its status, its retrieval time, and when it
is unavailable, why. This is where "source unavailable" lives, and it must stay
visibly different from a section with zero records.

**`origin`.** The geocode match. The matched address, the block range, the
street side, and the fact that the point locates a block rather than a parcel.
`lib/adapters/census.ts` already produces this.

**`group`.** Several records the grouping rules tied together: two EPA site IDs
under one registry ID, one site carrying two different names, two sources
disagreeing on a coordinate. `lib/report/grouping.ts` is being written in
parallel by another agent and will export the group shape. **Do not create that
file and do not import it.** Define the scope so a group of records can be
rendered, and leave the wiring to a later unit.

## What must stay true

Every guarantee the kernel already has. Specifically:

- A clause with no field reference still fails to compile.
- A clause interpolating a plain string still fails to compile.
- A template still cannot render a subject of the wrong shape.
- Rendering and tracing stay pure reads of the store, with nothing cached, which
  is what makes a deleted record leave no text behind.
- `bash .dev/census/mutation-check.sh` still reports six of six.

Widening the subject is safe precisely because purity, not record-scoping, is
what guarantees deletion. Arm C established that and arm B missed it. If you
find yourself adding a cache to make a scope work, stop and reconsider.

## SCOPE

`lib/evidence/sentence.ts`, `lib/evidence/templates.ts`, `lib/evidence/index.ts`,
`lib/templates/**`, `tests/unit/evidence/**`.

Not `lib/adapters/**`, not `lib/report/**`, not `app/`, not `docs/`, not `.dev/`,
not `tests/fixtures/`.

## ACCEPTANCE

- `pnpm verify` green. Paste the real output.
- `bash .dev/census/mutation-check.sh` reports six of six. If you moved code a
  mutation targets, fix its sed expression and say so.
- A test renders "EPA's Superfund inventory lists 15 sites within 5 miles of the
  mapped point" from the committed fixtures, asserting the literal sentence.
- **A test removes one record from the store and asserts that same sentence now
  reads 14, with no other change.** This is the guarantee the scope exists for.
- A test traces the count and asserts it carries the boundary, the endpoint and
  the record IDs behind it.
- A test renders the two NPL sites within 5 miles as their own sentence.
- A test renders a source-unavailable claim and asserts it is distinguishable
  from a section with zero records.
- A test renders the origin claim including the block range and the
  block-not-parcel wording.
- A compile-failure test per new scope, proving a template cannot render the
  wrong subject shape.
- Zero type assertions, non-null assertions or `any` under `lib/evidence/`.

## FORBIDDEN

No new dependencies. No network. No git commands, leave the tree dirty. Do not
weaken an existing test; update one only where a change legitimately alters
behaviour, and say which and why.

## TIMEBOX

properly with its deletion test and name exactly what is undone.

## REPORT, 25 lines maximum

Files changed. Real `pnpm verify` and mutation-check output. Each scope marked
