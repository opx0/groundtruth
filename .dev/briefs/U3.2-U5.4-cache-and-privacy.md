# U3.2 and U5.4 — the coordinate cache, and the privacy tests that are commands

Two units that share one subject: what the server remembers, and proving it
remembers nothing it must not.

## U3.2 — the coordinate cache

`docs/BRIEF.md` B9, last paragraph:

> Bounded in-memory coordinate cache: AirNow 10 minutes; geocoder none; ECHO,
> FRS, SEMS, AQS, FEMA 60 minutes. The cache dies with the process. Expired
> data never renders as current.

And, two lines above it: **no cache key tied to a user, session, IP, or
browser.**

That last line is the whole design constraint, and it is easier to hold than it
looks, because the only thing worth keying on is the request itself: a point, a
radius, and the URL an adapter asked for. None of those is a person. The thing
to be careful about is the *coordinate*: it is not a person either, but it is
the most identifying value in the system, and a cache that keeps it keyed in
memory for an hour is the closest this codebase comes to a database of
searches. Decide deliberately what the key is, say why it cannot identify
anyone, and say what an operator would see if they took a heap dump.

Four things that are not optional:

- **Expired data never renders as current.** A hit past its TTL is a miss, and
  the retrieval time a record carries is the time it was *fetched*, never the
  time it was served from the cache. A cached record's `retrievedAt` and its
  payload's `retrievedAt` must still be the moment the bytes arrived — that is
  what the trace panel shows and what B12's rendering tests assert.
- **The cache dies with the process.** No file, no external store, no
  `globalThis` that survives a reload in dev.
- **Bounded.** An unbounded map keyed on coordinates is a slow leak with a
  privacy shape. Name the bound and what happens at it.
- **The geocoder is never cached.** B9 says none, and it is the one request
  that carries an address.

Where it goes: `SourceIo` is the seam every adapter fetches through, which
makes a caching `SourceIo` that wraps another one the natural shape — one
decorator, no adapter changes, and the TTL table in one place. Consider it and
say what you chose. Note that `SourceIo.now()` is also the clock the kernel
stamps outcomes with; a cache that freezes `now` would freeze every retrieval
time with it.

## U5.4 — the privacy tests

`docs/BRIEF.md` B12, fourth paragraph:

> Privacy tests prove: environmental adapters never receive the raw address;
> logs redact addresses and coordinates; client bundles contain no keys;
> fixtures cannot enter a production build; cache entries carry no user or
> session identifier.

Four of those five have been proved once, by an audit that ran in a throwaway
suite and deleted itself. That is worth exactly nothing to the next person. The
unit is to make each one a test in the repo that fails when the property does.

Everything below was verified by that audit, so none of it is speculative —
what is missing is the committed test:

1. **No address reaches an environmental adapter.** True by the shape of the
   request today: `ReportRequestSchema` is a strict object of two numbers, so a
   body carrying an address is a 400 and no source is asked. Twelve shapes were
   tried, including a `__proto__` smuggle and a coordinate-plus-address body.
   Pin it, and pin that the route reads nothing else off the request — no
   header, no cookie, no URL parameter — because a coordinate in a query string
   would land in an access log.
2. **Logs carry nothing derived from the request.** There are exactly three
   `console` calls in `app/` and `lib/`, all fixed strings, one with a
   `FailureCause` enum value. Capture the console across a timeout, a refusal,
   a malformed body, an invalid request, and a whole-report failure, and assert
   what was written. The whole-report failure is the sharp one: the error that
   causes it can carry a coordinate in its message, and must not be logged.
3. **Client bundles contain no keys.** A real `pnpm build`, then grep
   `.next/static`. This is the one test that has to shell out; make it skippable
   by an env var if it is too slow for the default suite, and say which you
   chose.
4. **Fixtures cannot enter a production build.** Nothing under `lib/` or `app/`
   may import from `tests/`. Assert it structurally rather than by grep if you
   can — a lint rule is stronger than a test, and `eslint.config.mjs` already
   enforces one such rule for `lib/evidence/`.
5. **Cache entries carry no user or session identifier.** Yours to write, with
   U3.2. Assert the key, not the intention.

One more, not in B12 but proved by the same audit and worth keeping: **no
configured credential reaches the wire**, in any spelling. There are tests for
this in `tests/unit/app/report-route.test.ts`; make sure they cover a key in a
path and a key in a fragment, not only a query parameter.

## Scope

Two agents.

**Cache**: `lib/io/cache-source-io.ts` (or whatever you name it),
`tests/unit/app/cache-source-io.test.ts`, and the one line in
`app/api/report/route.ts` that wraps the real io. Nothing else.

**Privacy**: `tests/unit/app/privacy.test.ts` and, if you take the lint-rule
route, `eslint.config.mjs`. Nothing else.

Read anything. If a property cannot be tested without changing production code,
that is a finding: report it rather than changing it.

## Acceptance

1. `pnpm verify` green and `bash .dev/census/mutation-check.sh` 8 of 8. Paste
   real output.
2. Every test names the B9 or B12 line it proves, in its own description.
3. For each privacy test, say what you ran to confirm it fails when the
   property is broken. A privacy test that cannot fail is worse than none: it
   is a claim with evidence attached that does not hold it up.
4. The cache: a test proves a hit inside the TTL avoids the request, a test
   proves a hit past the TTL makes it, and a test proves a served record's
   retrieval time is when the bytes arrived rather than when they were served.
5. Zero type assertions, non-null assertions or `any`.

## Forbidden

No new dependencies. No network. No git. No cache that outlives the process.

## Report, 20 lines maximum

The cache's key and why it identifies nobody. The TTL table and where it lives.
One line per B12 privacy line: the test, and what you ran to watch it fail.
Anything you could not prove without changing production code.
