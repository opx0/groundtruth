# U5.1 — the seven cases, for every source

`docs/BRIEF.md` B12, first paragraph:

> Adapter tests, per source, from recorded fixtures: success; no records;
> missing optional fields; unknown status; malformed response; rate limit;
> timeout. Assertions are literal normalized records, including units,
> timestamps, IDs, and provenance.

The two air adapters were built to this list and have all seven. The five
older adapters were built before it was a checklist and are missing cases —
mostly rate limit and timeout, which nothing has ever exercised for them.

This is the last item in the exit predicate that is not a command.

## What "the seven cases" means for a source that has no such state

Do not invent a state to fill a row. Three of the seven are about the
transport and are the same for every source; four are about the response and
some sources genuinely do not have them:

- **Success** and **no records** — every source has both, and every one of
  these already exists. Check rather than assume.
- **Missing optional fields** — a real row with a null where a null is allowed.
  Prefer a committed fixture that really has one over a derived row; several
  do.
- **Unknown status** — a status string the code has never catalogued, passed
  through verbatim. A source with no status vocabulary does not have this case:
  say so in the test file, name the reason, and do not fabricate one. The
  Census geocoder is one such source — it carries no status field and no match
  type, which `lib/adapters/census.ts` documents.
- **Malformed response** — a body the schema rejects. Note that for ArcGIS and
  ECHO this arrives with HTTP 200, and both already have that case; what may be
  missing is a body that is not JSON at all.
- **Rate limit** — `SourceFailure("rate-limited", <code>, <retry-after>)`, and
  the record of what the source actually does. `tests/fixtures/aqs/rate-limited.json`
  is the only recorded one in the repo: a real 429 with `Retry-After: 86400`.
  For a source that has never rate-limited us, the test drives the failure
  through the io and asserts the outcome carries the source's own code and
  retry hint rather than being flattened into "unknown".
- **Timeout** — the same, for `SourceFailure("timeout")`. The thing worth
  asserting is not that it fails; it is that it fails as *unavailable* and
  never as an empty result, because "no records" and "we could not ask" are the
  distinction the whole product rests on.

## The assertion standard

B12 says "literal normalized records, including units, timestamps, IDs, and
provenance". A test that asserts `outcome.status === "unavailable"` and stops
has checked the easy half. For each new case also assert what the reader would
see: the cause, the raw code the source sent, the retry hint, and — where the
source answered at all — the exact normalized value and the provenance entry
behind it.

## Scope

Five agents, one adapter test file each, fully disjoint:

- `tests/unit/adapters/census.test.ts`
- `tests/unit/adapters/sems.test.ts`
- `tests/unit/adapters/echo.test.ts`
- `tests/unit/adapters/fema.test.ts`
- `tests/unit/adapters/frs.test.ts`

You own your one test file. You may add fixtures under your source's own
`tests/fixtures/<source>/` directory, under the `derived-` rule if you author
them: a `derived-` prefix, a sibling `.source.md` naming where the shape came
from and the date, and wording no reader could mistake for captured bytes.
Prefer using a committed recording over authoring anything.

Read anything. Write nothing else — not the adapter, not the kernel, not
another source's tests. If a case cannot be written without changing the
adapter, that is a finding: report it with the reason rather than changing it.

## Acceptance

1. `pnpm exec vitest run <your test file>` green, `pnpm exec eslint <your file>`
   clean. Paste real output.
2. A table in your report: the seven cases down the side, and for each one
   either the test that covers it or the reason that case does not exist for
   this source. "Covered" means a test that fails if the behaviour changes —
   say what you ran to confirm that for each case you added.
3. Zero type assertions, non-null assertions or `any`.

## Forbidden

No new dependencies. No network — this is the one place a live-endpoint test
would make the suite flaky, and the existing live tests are skipped for that
reason. No git.

## Report, 15 lines maximum

The table from acceptance 2, and nothing else except real command output and
anything you found wrong with the adapter while writing them.
